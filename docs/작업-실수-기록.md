# 작업 실수 기록 — 같은 실수를 반복하지 않기 위한 문서

2026-08-09 온라인 멀티플레이·설정 화면 작업 중 사용자에게 지적받은 실수들과
각각의 재발 방지 규칙. CLAUDE.md가 이 문서를 링크한다. 새 실수가 지적되면 여기에 추가할 것.

## 금지 사항

- **Playwright(헤드리스 브라우저) 사용 금지.** 사용자 명시 지시 (2026-08-09).
  화면 확인이 필요하면 사용자에게 스크린샷을 요청한다.

## 실수와 재발 방지 규칙

### 1. 화면을 못 보면서 "됐다"고 보고함
- **실수**: 렌더 결과를 확인할 수단 없이 코드만 보고 완료 보고 → 사용자가 확인하면 어긋나 있음.
  같은 요청("패널 애니메이션")을 세 번 받게 만듦.
- **규칙**: 시각적 변경은 "됐다" 단정 금지. 계측(grep 카운트·헤드리스 테스트의 클래스 적용 횟수 등)으로
  적용 사실을 확인해 근거와 함께 보고하고, 최종 판단은 사용자 확인에 맡긴다.

### 2. 지적받은 지점 하나만 고침
- **실수**: "봇 아이콘 넣어줘" → 보드에만 넣고 패널·점수·대기실 누락. "봇 이름 바꿔" → 대기실만 고치고
  설정 폼 누락. 사용자가 "언제까지 일일이 말해줘야 하냐"고 반복 지적.
- **규칙**: 하나를 고치기 전에 같은 패턴이 쓰이는 곳을 grep으로 전수 조사해 한 번에 고친다.

### 3. 변경마다 커밋·푸시
- **실수**: 자잘한 수정 하나하나를 즉시 커밋·푸시해 이력을 오염시킴.
- **규칙**: 워킹 트리에 쌓아두고, 사용자가 화면으로 확인했거나 명시 요청할 때만 의미 단위로 커밋.

### 4. 시각적 지시를 상상으로 해석
- **실수**: "내 이름 옆에 버튼" → 입력창 옆 큰 버튼(라벨 옆이 정답), "대기실 자리 N" → 설정 폼(사용자가
  가리킨 화면과 다른 곳 수정), "0.3초 딜레이" → 잘못된 위치에 적용.
- **규칙**: 위치·모양 지시가 조금이라도 모호하면 짧게 한 번 확인하거나, 스크린샷을 요청한다.
  선택지를 제시할 때는 실제 화면 기준으로 정확히 묘사한다.

### 5. 만든 코드를 연결하지 않음
- **실수**: 애니메이션 이어재생 함수(fxTimeSync)를 정의만 하고 render()에서 호출하지 않아
  "고쳤다"고 두 번 보고함. 스페이서 클래스(aos-sp)를 마크업에 쓰고 CSS 정의를 빠뜨림.
- **규칙**: 새 함수·클래스를 추가하면 정의–호출/정의–사용 짝을 grep으로 확인한 뒤 보고한다.

### 6. 연관 상수를 함께 갱신하지 않음
- **실수**: CSS 애니메이션 길이를 늘리면서 JS 홀드 상수(FX_HOLD)를 안 맞춰 "봇 애니메이션이
  끝나기 전에 내 패널이 뜨는" 버그를 만듦 — 주석에 "같이 바꿀 것"이라 적혀 있었는데도.
- **규칙**: 값을 바꿀 때 그 값을 언급하는 주석·상수를 grep으로 찾아 함께 갱신한다.

### 7. 요청하지 않은 확장을 마음대로 함
- **실수**: "마지막 플레이어 뒤 딜레이"를 봇 간 간격 전체로 확장 적용해 게임을 굼뜨게 만듦.
- **규칙**: 요청의 범위를 넘는 동작 변화는 넣지 않는다. 필요해 보이면 제안만 한다.

### 8. 개발 환경 함정을 방치
- **실수**: 로컬 서버가 js를 캐시하는 채로 안내해, 사용자가 고쳐진 것을 보지 못하는 상태로
  여러 번 확인하게 만들었을 가능성.
- **규칙**: 로컬 확인용 서버는 캐시 무효화(no-store)로 띄운다 (tools 참고).

### 9. CSS를 파일 앞쪽에 넣어 조용히 덮어씌움
- **실수**: 모바일용 미디어 쿼리를 game.css 위쪽에 넣었는데, `.overlay`·`.modal`·`.ap-rolecell` 같은
  기본 규칙이 파일 **뒤쪽**에 있어 같은 특정도로 나중에 나와 이겼다. 넣은 규칙의 절반이 적용되지 않은 채
  "고쳤다"고 보고했고, 사용자가 "개판인데"라고 지적해서야 발견했다.
- **규칙**: 새 미디어 쿼리 블록은 **파일 끝**에 둔다. 그리고 "적용됐다"는 계산이 아니라
  **실제 computed 값**(getComputedStyle·getBoundingClientRect)으로 확인한다.

### 10. 특정도가 더 높은 기본 규칙이 미디어 쿼리를 이김
- **실수**: 모바일에서 보드 폭 애니메이션을 끄려고 `.pboard.board-in{animation:none}`(0,2,0)을 넣었는데,
  파일 밖의 `.pboard.board-in.cardflash`(0,3,0)가 이겨서 애니메이션이 되살아났다.
  그 애니메이션은 `--cbw` 기본값 118px에서 시작하는데 모바일에선 `--cbw`를 안 쓰므로,
  일꾼 배치 때(그때만 .cardflash가 붙는다) 펼친 보드가 118px로 찌그러졌다.
- **규칙**: 어떤 규칙을 미디어 쿼리에서 끌 때는 **그 속성을 쓰는 모든 선택자 조합**을 grep해
  가장 높은 특정도에 맞춰 끈다.

### 11. 단축 속성이 앞선 개별 속성을 덮음
- **실수**: 1000px 블록에서 `.wrap{padding-bottom:112px}`(액션바 자리)를 줬는데,
  640px 블록의 `.wrap{padding:6px 10px 36px}` 단축 속성이 폰 폭에서만 그것을 덮어써
  하단 액션바가 건설 부지를 가렸다.
- **규칙**: 좁은 화면 블록에서는 `padding`/`margin` 단축 대신 필요한 방향만 지정한다.

### 12. 브라우저가 멈춘 것을 코드 버그로 오진
- **실수**: 자동 클릭으로 한 판을 돌리다 탭이 멈추자 "게임에 멈춤 버그가 있다"고 보고했다.
  실제로는 **백그라운드 탭의 타이머 스로틀링**이었다(`setTimeout(200)`이 5초 넘게 걸리고
  `requestAnimationFrame`은 아예 안 돈다). 원래 코드에서도 똑같이 재현된 시점에 의심했어야 했다.
- **규칙**: 브라우저에서 확인할 때는 `document.visibilityState`를 먼저 본다.
  숨은 탭에서는 **타이머에 기대지 말고** 엔진을 동기로 호출해(`aiDecide()`·`actXxx()`) 진행시킨다.

### 13. 테스트가 쓰는 진입점을 가드로 막음
- **실수**: "이전 게임의 봇 타이머가 새 게임에 끼어드는" 버그를 고치려고 `aiDecide()`에
  "봇이 아니면 리턴" 가드를 넣었다. 그런데 `tools/nettest.js`는 **사람 좌석을 대신 두는 용도로**
  `aiDecide()`를 부른다 — 루프백 테스트가 통째로 멈췄다.
- **규칙**: 공용 함수에 가드를 넣기 전에 `grep -rn "함수명" js/ tools/`로 호출처를 전수 조사한다.
  (이 버그의 올바른 수정은 타이머를 걸 때의 `G`를 기억해 발동 시점에 대조하는 것이었다 — app.js)
